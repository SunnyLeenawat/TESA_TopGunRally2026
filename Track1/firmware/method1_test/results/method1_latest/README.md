# Calibration วันที่ 18 พฤศจิกายน 2026

ใช้ข้อมูลใหม่ 4 ไฟล์จาก `data/` ค่า C ละ 15 batches รวม 3,840 readings ทั้งหมด `ok` และ CPU 240 MHz เก็บชื่อไฟล์และ SHA-256 ใน [calibration.json](calibration.json) ไม่แก้ไฟล์ดิบหรือกู้ไฟล์เก่าที่ผู้ใช้ลบ

- batches 1–10 ต่อ C: สร้าง calibration
- batches 11–15 ต่อ C: ตรวจผล ไม่ใช้ปรับจุด calibration กลับเข้าไปอีก
- แต่ละ batch ใช้มัธยฐาน cycle count ทั้ง 64 ครั้ง หารด้วย 240 MHz เหมือน firmware

## วิธีคำนวณใหม่

ใช้เส้นตรงเดียวสำหรับ C ที่ไม่ทราบค่า ไม่ปัดผลให้ตรง 5/10/15/20 pF:

`C_pf = 3.0056397587854788 * median_elapsed_us - 17.859153176057443`

เลือกจากการเว้น C หนึ่งค่าออกจากข้อมูลฝึกแล้วทำนายกลับ: เส้นตรง RMSE 0.423 pF, แบบแบ่งช่วง 0.563 pF, กำลังสอง 1.022 pF จึงเลือกเส้นตรง ข้อมูลฝึกมีเพียง 4 ระดับ การเว้น 5 และ 20 pF เป็นการ extrapolate จึงยังไม่รับรองความแม่นยำกับ C สุ่มทั้งหมด

| C ตามป้าย (pF) | ค่าเฉลี่ยเวลามัธยฐานจาก 10 batches (µs) |
| --- | ---: |
| 5 | 7.5897916667 |
| 10 | 9.2422916667 |
| 15 | 11.0447916667 |
| 20 | 12.5260416667 |

ตารางเวลาเป็นข้อมูลสรุปเพื่ออ้างอิงเท่านั้น โค้ดใช้สมการเส้นตรงเดียวข้างบน ไม่มีตารางแบ่งช่วงหรือ clamp ผล ค่านอกช่วง 5–20 pF ยังไม่รับรอง

## ผลจาก batches 11–15

ค่าตารางคือผลคำนวณย้อนหลังจากข้อมูลชุดตรวจ โดยปัดรายครั้งเป็นสองตำแหน่งก่อนคิดคะแนน ไม่ใช่ผลวัดบนบอร์ดด้วย firmware ใหม่

| C ตามป้าย | ค่าเฉลี่ยเดิม | ค่าเฉลี่ยใหม่ | คะแนนใหม่ Accuracy + RMSE |
| --- | ---: | ---: | ---: |
| 5 pF | 5.336 | 4.976 | 10 + 9 |
| 10 pF | 10.244 | 9.944 | 10 + 8 |
| 15 pF | 15.570 | 15.336 | 5 + 3 |
| 20 pF | 19.978 | 19.796 | 7 + 5 |

สูตรกรรมการตามที่ผู้ใช้ยืนยัน: `Error = abs(mean - reference) * 100` และ `RMSE = sqrt(mean((reading-reference)^2)) * 100` ใช้ตัวเลขหน่วย pF ไม่หารด้วย reference จุดขอบที่กติกาเว้นไว้ เช่น 15 ของ Accuracy หรือ 5 ของ RMSE จะคืนคะแนน `null` เพื่อไม่เดากติกา

RMSE ก่อนปัดของชุดตรวจ: สมการเดิม 0.359 pF; เส้นตรง fit ใหม่ 0.209 pF; กำลังสอง 0.171 pF; แบบแบ่งช่วง 0.072 pF แม้แบบแบ่งช่วงดูดีกว่าบน C ชุดเดิม แต่เลือกเส้นตรงจากเกณฑ์ทำนาย C ที่เว้นออก ไม่เลือกจากคะแนน C ที่รู้ค่าแล้ว

**ข้อจำกัด:** ชุดตรวจเคยถูกเปิดดูในการวิเคราะห์ก่อนหน้าแล้ว จึงไม่ใช่ blind test ต้องมีรอบใหม่ยืนยัน ตัวอย่างตรวจยังเป็น C ชุดเดิมและ session เดิม ไม่ใช่ C ที่ไม่ทราบค่า ไม่มีหลักฐานว่าทุกค่าระหว่างจุดจะผ่านเกณฑ์คะแนน ตัวอ้างอิงมี tolerance +/-5% และค่าตามป้ายอาจไม่ใช่ค่ามาตรฐานของกรรมการ โดยเฉพาะผลช่วง 15 pF ยังมี bias ที่เส้นตรงเดียวแก้ไม่หมด

ข้อมูลมาจากโค้ดเทส ไม่ใช่โค้ดแข่งรุ่นใหม่ คงวงจรและ pot ใกล้ 900 mV ตามเดิม แล้วตรวจบอร์ดจริงหลังอัปโหลด ช่วงตรวจ reference 700–1100 mV ในโค้ดไม่ได้รับรองว่า calibration ใช้ได้เท่ากันทุกแรงดัน

## วิธีใช้และสร้างซ้ำ

โค้ดเทสและโค้ดแข่งใช้ `calibration_model.h` เหมือนกัน ต้องเก็บไฟล์นี้ไว้ในโฟลเดอร์เดียวกับแต่ละ `.ino` เปิดโค้ดแข่งใน Arduino IDE แล้ว Verify/Upload จากนั้นวัด C ทั้งสี่ค่าอย่างละ 5 ครั้ง

รันจากราก repository:

```powershell
.venv/Scripts/python.exe Track1/firmware/method1_test/calibrate_latest.py --write-headers
.venv/Scripts/python.exe -m unittest discover -s Track1/firmware/method1_test -p test_competition_score.py
```

โค้ดแข่งเริ่มต้นในโหมดรายงานปกติ กดสวิตช์เพื่อวัด หากต้องตรวจเวลา ส่ง `d` เพื่อเปิด diagnostic แล้วส่ง `m` เพื่อวัด จะมีบรรทัด `DIAG` ตามหลังผล ส่ง `q` หรือรีเซ็ตเพื่อกลับโหมดแข่ง ก่อนส่งจริงต้องไม่มีบรรทัด diagnostic สคริปต์ capture เดิมยังใช้กับโค้ดเทสเท่านั้น
