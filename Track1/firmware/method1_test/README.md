# วิธีที่ 1: วัดเวลาชาร์จ RC ด้วย LM393

คู่มือนี้ใช้กับ **DOIT ESP32 DEVKIT V1 (ESP32-WROOM-32)** เป้าหมายคือเก็บเวลาชาร์จของตัวเก็บประจุ 5, 10, 15 และ 20 pF แล้วนำไปสร้างกราฟเพื่อประเมินวิธีวัดและสอบเทียบ

## เก็บอัตโนมัติผ่าน PuTTY (โค้ดเทสรุ่นล่าสุด)

1. อัปโหลด `method1_test.ino` แล้วปิด Arduino Serial Monitor และสคริปต์ capture
2. เปิด PuTTY ที่ COM ของบอร์ด, 9600 baud, 8N1, flow control None ตั้ง Logging เป็น All session output ใช้ไฟล์ใหม่แยกตาม C เช่น `data/putty_10pf.log`
3. ต่อ C ค่าเดียวและคงสายกับ potentiometer ไว้ พิมพ์ **`run` แล้วกด Enter** จะวัดอัตโนมัติ 15 batches โดยไม่ต้องกดสวิตช์ แต่ละ batch วัด 64 readings แล้วส่งมัธยฐานเวลาและค่า pF
4. รอ `RUN_DONE,15` ประมาณ 15–20 วินาที อย่าเปลี่ยน C ระหว่างทำงาน หากต้องยกเลิก พิมพ์ `stop` แล้ว Enter จะหยุดก่อน batch ถัดไป
5. ปิด PuTTY เพื่อจบไฟล์ แล้วใช้คำสั่ง import/fit ใน [คู่มือ calibration](../method1_competition/PUTTY_CALIBRATION.md) ได้เลย `CAL_DATA` มีรูปแบบเดียวกัน ไม่ต้องพิมพ์ c/q สำหรับโค้ดเทส

ตัวอย่างรูปแบบเท่านั้น:

```text
RUN_START,15
CAL_HEADER,run,median_us,reference_mv,cpu_mhz,status
CAL_DATA,1,12.237500,902,240,ok
TGR-55
Capacitance = 21.01 pF

```

ค่า pF คำนวณจาก coefficient ที่เปิดใช้อยู่ใน `.ino` ส่วนการ fit ใหม่ใช้เวลาใน CAL_DATA โดยตรง หาก status ไม่ใช่ ok ห้ามนำไป fit แม้โปรแกรมจะทำครบ 15 batches ต้องตรวจวงจรแล้วเก็บ log ใหม่ การวัดที่คำนวณ pF ไม่เป็นบวกแสดง 0.00 ตามเดิม แต่เวลาอาจยังเป็น ok และใช้สอบเทียบได้

คำสั่ง `r` + Enter ตรวจ reference, `m` + Enter วัดหนึ่ง batch พร้อม CSV ดิบ 64 แถว จึงยังรองรับ `capture_serial.py` แบบเดิมได้ ปุ่มจริงยังวัดได้เมื่อไม่มี automatic run คำสั่งทั้งหมดต้องลงท้าย Enter (CR หรือ LF) log หนึ่งไฟล์ให้มี run เดียวครบ 15 batches ห้าม append หลายรอบเพราะเลข run จะเริ่ม 1 ใหม่

**Calibration ปัจจุบัน:** คืนค่ารอบแรกวันที่ 17 พฤศจิกายนสำหรับ breadboard ตัวแรกแล้ว ทั้งสอง sketch ใช้ `C_pf = 3.0739224418808453 * median_elapsed_us - 18.352037372425478` ใน `calibration_model.h` ตาม [ไฟล์ต้นฉบับ](results/method1_session1/calibration.json) การวิเคราะห์รอบหลังด้านล่างเป็นประวัติ ไม่ใช่ calibration ปัจจุบัน ยังไม่ได้อัปโหลดรุ่นที่คืนค่านี้ ต้องตรวจซ้ำเมื่อประกอบวงจรกลับ และแยกข้อมูลคนละ breadboard อย่ารัน `calibrate_latest.py --write-headers` ทับค่าที่คืนไว้โดยไม่ตั้งใจ

**สถานะ:** ยังไม่ได้ยืนยันการคอมไพล์กับ Arduino IDE ของทีมและยังไม่ได้ทดสอบวงจรจริง โปรแกรมนี้รายงานเวลาที่วัดได้ ยังไม่ใช่ค่าความจุที่สอบเทียบแล้ว และยังไม่มีรูปแบบข้อความ/LED สำหรับส่งแข่ง

## 1. หลักการทำงาน

GPIO25 ส่งแรงดันผ่านตัวต้านทาน 1 MOhm ไปชาร์จตัวเก็บประจุ LM393 เปรียบเทียบแรงดันที่ตัวเก็บประจุกับแรงดันอ้างอิงประมาณ 900 mV เมื่อแรงดันตัวเก็บประจุสูงกว่าแรงดันอ้างอิง เอาต์พุตจะเปลี่ยนจาก HIGH เป็น LOW โปรแกรมรับสัญญาณที่ GPIO27 และบันทึกเวลาที่ผ่านไป

หนึ่งการกดปุ่มหรือส่งคำสั่ง `m` จะวัดภายใน **64 ครั้ง** เก็บข้อมูลไว้ก่อน แล้วจึงส่ง CSV ออก เพื่อไม่ให้การพิมพ์ข้อความรบกวนช่วงจับเวลา

## 2. Dependencies และการติดตั้ง Arduino IDE

| รายการ | ค่าที่ใช้ |

| Arduino IDE | 2.x และบันทึกเลขรุ่นที่ติดตั้งจริง |
| แพ็กเกจบอร์ด | esp32 by Espressif Systems รุ่น **3.3.0** |
| บอร์ด | **DOIT ESP32 DEVKIT V1** |

`Arduino.h`, `driver/gpio.h` และคำสั่ง ESP32 มาพร้อมแพ็กเกจบอร์ด ไม่ต้องติดตั้งไลบรารี LM393 เพิ่ม ส่วน `sketch.yaml` เป็น build profile สำหรับ Arduino CLI ผู้ใช้ Arduino IDE ต้องติดตั้งและเลือกบอร์ดเองตามขั้นตอนนี้

### ขั้นตอนที่ 1: เพิ่ม URL และติดตั้งแพ็กเกจ

1. เปิด **File > Preferences** แล้วหา **Additional Boards Manager URLs**
2. เพิ่ม URL ด้านล่าง โดยเก็บ URL เดิมไว้ถ้ามี แล้วกด OK

   ```text
   https://espressif.github.io/arduino-esp32/package_esp32_index.json
   ```

3. เปิด **Boards Manager** จากแถบด้านข้างหรือ **Tools > Board > Boards Manager**
4. ค้นหา `esp32` เลือกรายการของ **Espressif Systems** เลือกรุ่น **3.3.0** แล้วกด Install รอจนเสร็จ
5. ใช้ core รุ่นเดียวกันตลอดการทดลอง หากเปลี่ยนรุ่นให้แก้ README และ `sketch.yaml` พร้อมตรวจ calibration ใหม่ รุ่นที่ระบุเป็น baseline ของโครงการ ไม่ใช่การรับรองว่าคอมไพล์หรือทดสอบผ่านแล้ว

### ขั้นตอนที่ 2: เลือกบอร์ดและพอร์ต

1. เปิด `method1_test.ino` ในโฟลเดอร์ `method1_test` โดยรักษาชื่อไฟล์หลักและชื่อโฟลเดอร์ให้ตรงกัน
2. ต่อ ESP32 กับคอมพิวเตอร์ด้วยสาย USB ที่ส่งข้อมูลได้
3. เลือก **Tools > Board > esp32 > DOIT ESP32 DEVKIT V1**
4. เลือก **Tools > Port** ให้ตรงกับบอร์ด หากไม่แน่ใจ ให้ดูว่าพอร์ตใดหายเมื่อถอด USB และกลับมาเมื่อเสียบใหม่
5. กด **Verify** เพื่อตรวจการคอมไพล์ก่อน หากมี error ให้เก็บข้อความเพื่อวิเคราะห์ก่อนอัปโหลด

## 3. เตรียมและต่อวงจร

**ถอด USB และแหล่งจ่ายไฟก่อนต่อหรือเปลี่ยนอุปกรณ์** เลข GPIO หมายถึงเลขบนบอร์ด เช่น GPIO25 ไม่ใช่การนับตำแหน่งขาจากหัวแถว

ใช้ LM393, potentiometer 10 kOhm, ตัวต้านทาน 1 MOhm และ **2 kOhm สำหรับ pullup เอาต์พุต LM393 ตามคำแนะนำของกรรมการ**, ตัวเก็บประจุ 100 nF, ปุ่มกด และตัวเก็บประจุที่จะทดสอบ ตัวต้านทาน 10 kOhm ยังไม่ใช้เป็น pullup ของ LM393 ส่วน potentiometer ยังคงเป็น 10 kOhm

สำหรับ LM393 **แบบ DIP-8** เมื่อมองจากด้านบนและหันรอยบากขึ้น ขา 1 อยู่ซ้ายบน นับลงทางซ้ายแล้ววนขึ้นทางขวา หากเป็นแพ็กเกจอื่นต้องตรวจ pinout ก่อน

```text
       รอยบาก
      +--U--+
 OUT1 |1   8| VCC
  IN- |2   7| OUT2
  IN+ |3   6| IN2-
  GND |4   5| IN2+
      +-----+
```

### ขั้นตอนที่ 3: ต่อไฟเลี้ยง

1. ต่อ ESP32 **3V3 ไป LM393 ขา 8** และ **GND ไปขา 4**
2. ทุกส่วนของวงจรใช้ GND ร่วมกัน
3. เก็บตัวเก็บประจุ **0.1 uF (100 nF)** ไว้ต่อคร่อมสวิตช์ในขั้นตอนที่ 6 ตามคำแนะนำของกรรมการ ชุดนี้มีตัวเดียว จึงไม่จัดสรรให้คร่อมขาไฟเลี้ยง LM393 และไม่ต่อเข้าจุดวัดตัวเก็บประจุ 5-20 pF

### ขั้นตอนที่ 4: ต่อแรงดันอ้างอิง

1. ตรวจว่าขาใดของ potentiometer เป็นปลายทั้งสองและขาใดเป็น wiper อย่าเดาจากตำแหน่งขาของ trimpot
2. ต่อปลายสองข้างเข้ากับ **3V3 และ GND**
3. ต่อ wiper ไปทั้ง **LM393 ขา 3 (+)** และ **GPIO34**
4. หลังเปิดโปรแกรม เราจะใช้คำสั่ง `r` เพื่อปรับแรงดันให้ประมาณ **900 mV หรือ 0.9 V**

GPIO34 อ่านเฉพาะแรงดันอ้างอิง ไม่ได้อ่านจุดวัดตัวเก็บประจุ เราไม่ใช้ 2.086 V ตามตัวอย่างสไลด์ เพราะอยู่นอกช่วง common-mode ของ LM393 รุ่นปกติเมื่อจ่ายไฟ 3.3 V ค่า ADC เป็นค่าประมาณ ไม่ใช่เครื่องมืออ้างอิงความแม่นยำสูง

### ขั้นตอนที่ 5: ต่อทางชาร์จ

1. ต่อ **GPIO25 ผ่านตัวต้านทาน 1 MOhm ไปยังจุดวัด C**
2. ต่อจุดวัด C ไป **LM393 ขา 2 (-)**
3. เมื่อต้องการวัด ให้ต่อ C ที่ทดสอบระหว่างจุดวัด C กับ GND สำหรับ baseline ครั้งแรกให้เว้นตัวเก็บประจุนี้ไว้ก่อน

```text
GPIO25 ---- 1 MOhm ----+---- LM393 ขา 2 (-)
                      |
                 C ที่ทดสอบ
                      |
                     GND
```

### ขั้นตอนที่ 6: ต่อเอาต์พุตและปุ่ม

1. ต่อ **LM393 ขา 1 ไป GPIO27**
2. ต่อตัวต้านทาน **2 kOhm ระหว่างขา 1 กับ 3V3** เป็น pullup ของ open-collector output ตามคำแนะนำของกรรมการ ห้ามดึงเอาต์พุตขึ้นไปที่ 5 V
3. ต่อสวิตช์ระหว่าง **GPIO26 กับ GND** โปรแกรมเปิด pullup ภายใน ESP32 แล้ว หากปุ่มมีสี่ขา ต้องเลือกคู่ที่เชื่อมกันเมื่อกด ไม่ใช่คู่ที่เชื่อมกันอยู่แล้ว
4. ต่อ **0.1 uF (100 nF) ขนานกับสวิตช์**: ขาหนึ่งไปจุด GPIO26 อีกขาไป GND เพื่อช่วยลดสัญญาณเด้งของปุ่มตามคำแนะนำของกรรมการ บน breadboard ขา C แต่ละข้างต้องอยู่กลุ่มรูเดียวกับปลายสวิตช์ด้านนั้น แต่ขา C ทั้งสองห้ามอยู่กลุ่มรูเดียวกัน ถ้าเป็นเซรามิกจะไม่มีขั้ว
5. comparator อีกตัวที่ไม่ใช้: ต่อ **ขา 5 ไป GND**, **ขา 6 ไป wiper** และเว้น **ขา 7**
6. ตรวจทิศ IC, ค่า R, ขา GPIO และตรวจว่าไม่มีสายเชื่อม 3V3 กับ GND โดยตรง ก่อนเสียบไฟ

```text
GPIO26 --------+---------+
               |         |
            สวิตช์    C 0.1 uF
               |         |
GND -----------+---------+
```

วงจรปุ่มนี้ใช้ `INPUT_PULLUP` ภายใน ESP32 และ software debounce 30 ms ตามโค้ดเดิม ตัวเก็บประจุช่วยกรองสัญญาณเด้ง แต่ยังคง software debounce ไว้ด้วย ส่วน pullup **2 kOhm** เป็นของเอาต์พุต LM393 ที่ GPIO27 ไม่ใช่ตัวต้านทานของปุ่ม

รักษาสายให้สั้นและอยู่ตำแหน่งเดิม ความจุแฝงจากสายและการสัมผัสอาจมีผลมากเมื่อวัดระดับ pF

### External interrupt และขอบสัญญาณ

โค้ดใช้ external GPIO interrupt ที่ **GPIO27** อยู่แล้ว โดยตั้งดังนี้:

```cpp
attachInterrupt(digitalPinToInterrupt(COMPARATOR_PIN), onCrossing, FALLING);
```

สำหรับวงจรนี้ LM393 ขา 3 (+) รับแรงดันอ้างอิง และขา 2 (-) รับแรงดันตัวเก็บประจุ เมื่อคายประจุแล้วเอาต์พุตควรเป็น HIGH จากนั้นเมื่อแรงดันชาร์จสูงกว่าแรงดันอ้างอิง เอาต์พุตจะลง LOW จึงจับ **FALLING (HIGH -> LOW)** เพื่อบันทึกเวลาข้าม threshold

```text
3V3 ---- R 2 kOhm ----+---- GPIO27 (interrupt: FALLING)
                     |
                 LM393 ขา 1
```

หากสลับขา + และ - เอาต์พุตขณะชาร์จจะเปลี่ยนเป็นขอบ RISING แต่ต้องปรับการตรวจสถานะเริ่มต้นในโค้ดด้วย ไม่ควรเปลี่ยนเฉพาะชื่อ trigger โค้ดปัจจุบันตรวจว่าเอาต์พุตเป็น HIGH ก่อนเริ่มชาร์จและรอ FALLING เพียงขอบเดียว

ปุ่ม GPIO26 ใช้เริ่ม batch ส่วน GPIO27 ใช้จับเวลาจาก comparator เป็นคนละหน้าที่ หลังเปลี่ยน pullup ให้เก็บ baseline และข้อมูลสอบเทียบใหม่ โดยบันทึกว่าใช้ R 2 kOhm

## 4. อัปโหลดและเริ่มทดลอง

### ขั้นตอนที่ 7: อัปโหลดและเปิด Serial Monitor

1. เสียบ USB ตรวจบอร์ดและพอร์ต แล้วกด **Upload** รอจน IDE แจ้งว่าสำเร็จ
2. เปิด **Serial Monitor** และตั้งเป็น **9600 baud**
3. ข้อความเริ่มต้นจะบอกว่า `r` อ่านแรงดัน และ `m` เริ่มวัด หากพลาดข้อความให้ส่ง `r` เพื่อตรวจการตอบกลับได้
4. ข้อความ bootloader ตอนรีเซ็ตอาจอ่านไม่ออกที่ 9600 ให้ดูการตอบคำสั่งของ sketch หลังบูตเป็นหลัก

### ขั้นตอนที่ 8: ปรับแรงดันอ้างอิง

1. พิมพ์ตัวเล็ก `r` แล้วกด Send หรือ Enter โปรแกรมตอบค่าเป็น **mV** เช่น `900` คือประมาณ 0.900 V
2. หมุน potentiometer ทีละน้อยแล้วส่ง `r` ซ้ำจนใกล้ 900 mV
3. ปล่อยมือและอ่านซ้ำเพื่อดูว่าค่านิ่งพอหรือไม่ โปรแกรมรับช่วง **700-1100 mV** หากนอกช่วงจะขึ้น `SET_REFERENCE` และไม่เริ่มวัด
4. อย่าปรับค่าอ้างอิงระหว่างเปรียบเทียบตัวเก็บประจุโดยไม่บันทึกการเปลี่ยนและสอบเทียบใหม่

### ขั้นตอนที่ 9: วัด baseline

1. เริ่มจากวงจรที่ยังไม่ใส่ C ที่ทดสอบ แต่คงสายอื่นเหมือนเดิม
2. ส่ง `m` ครั้งเดียวแล้วปล่อยมือห่างจากวงจร
3. รอหัวตาราง CSV และข้อมูล **64 แถว** ให้ส่งครบ เก็บไฟล์แยกโดยระบุ `open_fixture`
4. baseline นี้ไม่ใช่ตัวอ้างอิง 0 pF ที่ทราบค่าจริง เพราะสายและขา IC ยังมีความจุแฝง ถ้าวัดไม่ได้ให้เก็บสถานะผิดพลาดไว้ ไม่แทนด้วยศูนย์

### ขั้นตอนที่ 10: วัดตัวเก็บประจุทั้งสี่ค่า

1. ถอด USB ใส่ **5 pF** ระหว่างจุดวัด C กับ GND แล้วเสียบ USB ใหม่
2. ส่ง `r` ตรวจค่าอ้างอิง แล้วกดปุ่มหนึ่งครั้งแล้วปล่อย หรือส่ง `m` ครั้งเดียว ใช้อย่างใดอย่างหนึ่งต่อ batch
3. รอส่งข้อมูล 64 แถวครบก่อนเริ่ม batch ถัดไป ที่ 9600 baud การส่ง CSV ใช้เวลาหลายวินาที การส่งข้อมูลเกิดหลังการวัด
4. เก็บ **5 batches** สำหรับ 5 pF แล้วทำเหมือนกันกับ **10, 15 และ 20 pF** ถอดไฟทุกครั้งที่เปลี่ยนอุปกรณ์
5. ทำซ้ำ **3 sessions** ตาม Planning.md โดยมี power cycle และสลับลำดับค่าระหว่าง sessions เก็บวงจรและสายให้เหมือนเดิม

อย่ากดหรือส่ง `m` ซ้ำระหว่างกำลังพิมพ์ข้อมูล เพราะคำสั่ง Serial อาจค้างในบัฟเฟอร์และเริ่ม batch ใหม่ภายหลัง

หนึ่ง batch มี 64 การอ่านภายใน แต่ไม่ใช่ 64 การกดอิสระ ทั้งแผนมี 4 ค่า x 5 batches x 3 sessions = **60 batches** หรือสูงสุด 3,840 แถวภายใน ไม่รวม baseline

## 7. กราฟและการสอบเทียบ

เริ่มจากกราฟ **แกน X = ค่าความจุตามป้าย (pF)** และ **แกน Y = เวลาที่วัดได้ (us)** แสดงข้อมูลแต่ละ batch และความแปรปรวน พร้อมกราฟตามลำดับการอ่านและจำนวนครั้งที่ผิดพลาด

| ค่าตามป้าย | ช่วง tolerance +/-5% |
| --- | --- |
| 5 pF | 4.75-5.25 pF |
| 10 pF | 9.50-10.50 pF |
| 15 pF | 14.25-15.75 pF |
| 20 pF | 19.00-21.00 pF |

ใช้ error bar แนวนอนสำหรับ tolerance ของตัวอ้างอิง และแนวตั้งสำหรับความแปรปรวนของผลวัด โดยระบุสถิติให้ชัดเจน **+/-5% เป็น tolerance ของตัวเก็บประจุ ไม่ใช่ความแม่นยำที่รับรองให้เครื่องวัด** การเฉลี่ยไม่ทำให้ tolerance หายไป

สมการ RC อุดมคติเมื่อเริ่มจากคายประจุแล้ว:

```text
C = -t / (R * ln(1 - Vthreshold / Vcharge))
```

ใช้ t เป็นวินาที R เป็นโอห์ม ได้ C เป็นฟารัด และคูณ 1e12 เพื่อแปลงเป็น pF ห้ามใช้ `C = t/R` ตรง ๆ ที่ reference 900 mV เพราะสูตรย่อนั้นใช้เมื่อ threshold เท่ากับ 63.2% ของแรงดันชาร์จในกรณีอุดมคติ

เวลาจริงรวม GPIO/interrupt latency, comparator delay และความจุแฝง โปรแกรมจึงยังไม่รายงาน pF หลังเห็นว่าข้อมูลแยกค่าทั้งสี่ได้แล้ว จึง fit calibration และกันตัวอ้างอิงหนึ่งค่าออกเพื่อทดสอบตาม Planning.md หากเปลี่ยนวงจร สาย หรือ firmware ให้บันทึก revision และตรวจ calibration ใหม่

ผลลัพธ์อยู่ที่ `results/method1_session1/` การรันซ้ำจะสร้างผลวิเคราะห์ในโฟลเดอร์เดิม แต่ไม่แก้ไฟล์ข้อมูลดิบ:

| ไฟล์ | วิธีอ่าน |

| `02_validation.png` | เปรียบเทียบค่า pF จากสมการอุดมคติกับผลหลังสอบเทียบแบบกันตัวอ้างอิงออกทีละค่า และ residual เทียบค่าตามป้าย |

| `calibration.json` | สมการ ตัวชี้วัด รายการไฟล์ต้นทางพร้อม hash และข้อจำกัด |

ผลเบื้องต้นจากข้อมูลชุดนี้:

```text
C_estimated_pf = 3.07392244 * median_elapsed_us - 18.35203737
```

`median_elapsed_us` คือมัธยฐานของ 64 การอ่านในหนึ่ง batch ไม่ใช่การอ่านเดี่ยว ไม่ได้ลบแถวแรกหรือค่าอื่นออกจากไฟล์ดิบ สมการนี้ fit จากตัวอ้างอิงทั้งสี่ค่าและใช้ได้เบื้องต้นเฉพาะวงจร/การตั้งค่าเดิมในช่วงอ้างอิง 5-20 pF

การตรวจแบบ leave-one-capacitor-out กันทั้งห้า batches ของ C ค่านั้นออกก่อน fit และทำนายกลับ ผล RMSE เทียบค่าตามป้ายประมาณ **0.445 pF** ส่วน training RMSE ประมาณ **0.200 pF** ต้องไม่ใช้ตัวหลังแทนผลทดสอบอิสระ การกัน 5 และ 20 pF ออกเป็นการ extrapolate จากช่วงที่เหลือ

สูตรทฤษฎีในกราฟใช้ R ตามป้าย 1 MOhm, Vcharge สมมติ 3.3 V และ Vref จาก ADC จึงยังรวมความผิดพลาดจากความจุแฝงและความหน่วง ค่า pF ตามสูตรอุดมคติยังสูงกว่าค่าตามป้ายอย่างชัดเจนในข้อมูลนี้

ตัวอ้างอิงมี tolerance +/-5% ผลนี้จึงไม่ใช่การรับรอง absolute accuracy พื้นที่แรเงา calibration แสดงเฉพาะความไวต่อ tolerance ตัวอ้างอิง ไม่ใช่ confidence interval หรือความไม่แน่นอนรวมทั้งหมด ผลรอบแรกข้างบนเก็บไว้เป็นประวัติ ปัจจุบัน firmware ทั้งสองชุดใช้ calibration วันที่ 18 พฤศจิกายน ตามรายงานล่าสุดด้านล่าง

## Calibration เดิม: รวมสองรอบ (ถูกแทนที่แล้ว)

สมการเดิมคือ `C_pf = 2.9690151954173993 * median_elapsed_us - 17.219924456350515` จาก 40 batch medians เก็บ [ผลวิเคราะห์เดิม](results/method1_combined/calibration.json) ไว้เป็นประวัติ ปัจจุบันใช้ calibration linearจากข้อมูลวันที่ 18 พฤศจิกายนใน `calibration_model.h` ทั้งสอง sketch ดู [รายงานล่าสุดและวิธีสร้างซ้ำ](results/method1_latest/README.md) ต้องเก็บ header ไว้ข้าง `.ino` ด้วย

ผลย้อนหลังดีขึ้นบางช่วงโดยเฉพาะ 5 pF แต่ไม่ดีขึ้นทุกค่า ข้อมูลทั้งสองรอบถูกใช้ในการเลือกและสร้างสมการแล้ว ต้องเก็บรอบใหม่จากบอร์ดจริงเพื่อประเมินผลอิสระ ไม่ต้องเปลี่ยนวงจรหรือปรับ potentiometer เพื่อใช้สมการใหม่

## อ่านค่า capacitance จากโค้ดเทสเพื่อเทียบกับตัวแข่ง

1. อัปโหลด `method1_test.ino` รุ่นล่าสุด เปิด Serial Monitor ที่ 9600 baud
2. ต่อ C ที่ต้องการทดสอบ ใช้ `r` ตรวจแรงดันอ้างอิงใกล้ 900 mV แล้วส่ง `m` หรือกดปุ่มหนึ่งครั้ง
3. อ่านบรรทัด `SUMMARY Capacitance` ก่อนตาราง CSV ตัวอย่างรูปแบบ (ไม่ใช่ผลวัดจริง):

```text
SUMMARY run=1 valid=64/64 cpu_mhz=240
SUMMARY median_elapsed_us = 9.2234
SUMMARY Capacitance = 10.00 pF
```

ค่า pF หนึ่งค่ามาจากมัธยฐานของ 64 การอ่าน ใช้ cycle count ก่อนปัดทศนิยมและสมการเดียวกับ `method1_competition.ino` ไม่ใช่ค่า pF ของการอ่านเดี่ยว ถ้าไม่ครบ 64 แถวที่เป็น `ok`, CPU ไม่ใช่ 240 MHz หรือผลไม่เป็นบวก จะแสดง `INVALID` (ตัวแข่งใช้ 0.00 pF แจ้งความล้มเหลว) ถ้า reference นอกช่วงจะยังแสดง `SET_REFERENCE` ตามเดิม

การจับเวลายังทำก่อนคำนวณและพิมพ์ทั้งหมด เก็บ CSV รูปแบบเดิมครบ 64 แถวตามลำดับเดิม จึงใช้สคริปต์วิเคราะห์เดิมได้ เมื่อใช้ `capture_serial.py` ค่า SUMMARY จะแสดงใน terminal และบันทึกในไฟล์ `.txt` คู่กับ CSV ส่วน `.csv` ยังคงเก็บข้อมูลดิบ ไม่มีคอลัมน์ pF เพิ่ม

เพื่อเปรียบเทียบ ให้วัด C ตัวเดิมหลายครั้งด้วยโค้ดเทส จดค่า SUMMARY แล้วอัปโหลดโค้ดแข่งโดยไม่ขยับสายหรือปรับ pot เปรียบเทียบกับบรรทัด `Capacitance` ของตัวแข่ง สมการเดียวกันไม่ได้รับรองว่าผลจะเท่ากัน เพราะ firmware และสภาพวงจรอาจทำให้เวลาที่วัดเปลี่ยนได้
