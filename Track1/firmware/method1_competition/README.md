# Method 1 สำหรับแข่งขันวัดความจุ: TGR-55

Sketch นี้สำหรับการแข่งขันวัดความจุ pF ใช้ DOIT ESP32 DEVKIT V1, Arduino ESP32 core 3.3.0 และวงจร LM393 เดิม ไม่มีไลบรารีเพิ่มเติม ใช้รหัสทีม **TGR-55** ยังไม่ใช่โปรแกรมวัดความชื้นเมล็ดกาแฟ

## วงจรที่ต้องใช้

ใช้รายละเอียดการต่อวงจรใน [คู่มือตัวทดลอง](../method1_test/README.md) โดยคงค่าและตำแหน่งสายเดิม:

| ขา | การต่อ |
| --- | --- |
| GPIO25 | ผ่าน R 1 MOhm ไปจุด C และ LM393 ขา 2 (-) |
| LM393 ขา 3 (+) | wiper แรงดันอ้างอิงประมาณ 900 mV |
| GPIO34 | wiper เดียวกัน อ่านแรงดันอ้างอิง |
| LM393 ขา 1 | GPIO27 และ R pullup **2 kOhm ไป 3V3** |
| GPIO26 | สวิตช์ลง GND มี **0.1 uF คร่อมสวิตช์** และใช้ INPUT_PULLUP |
| GPIO2 | LED บนบอร์ด กำหนด HIGH = สว่าง ต้องตรวจบอร์ดจริง |
| LM393 ขา 8 / ขา 4 | 3V3 / GND |

จับ external interrupt แบบ **FALLING** เหมือนตัวทดลอง ห้ามสลับขา comparator หรือปรับ reference แล้วใช้ calibration เดิมโดยไม่ตรวจซ้ำ

## วิธีใช้งาน

1. ใช้ sketch ทดลองปรับ reference ใกล้ 900 mV และตรวจว่าได้ ok ครบก่อน
2. ปิด Python capture/Serial Monitor ที่ใช้ COM port อยู่
3. เปิด `method1_competition.ino` เลือก **DOIT ESP32 DEVKIT V1** และ COM port ที่ถูกต้อง แล้ว Verify และ Upload
4. เปิด Serial Monitor ที่ **9600 baud** รอให้บอร์ดบูตและปล่อยปุ่มก่อนกดครั้งแรก
5. กดสวิตช์หนึ่งครั้งแล้วปล่อย โปรแกรมจะอ่าน 64 ครั้ง หามัธยฐาน แปลงเป็น pF และพิมพ์หนึ่งชุดข้อความ พร้อม LED สว่างประมาณ 200 ms
6. รอผลและ LED ดับก่อนกดครั้งต่อไป การกดค้างไม่สร้างผลซ้ำ ต้องปล่อยให้ปุ่มกลับ HIGH อย่างน้อย 30 ms ก่อนเริ่มครั้งใหม่

ตัวอย่างรูปแบบข้อความเท่านั้น ไม่ใช่ผลวัดที่รับรอง:

```text
TGR-55
Capacitance = 10.00 pF

```

ไม่มีคำสั่ง r/m หรือ CSV ในตัวนี้ สคริปต์ `capture_serial.py` ของตัวทดลองใช้กับ output ตัวแข่งไม่ได้ ข้อความ ROM ตอนรีเซ็ตไม่ใช่ข้อความของ sketch ให้รอบอร์ดเริ่มทำงานก่อนกรรมการวัด

## Calibration ที่ใช้

```text
C_pf = 3.0739224418808453 * median_elapsed_us - 18.352037372425478
```

มาจาก [ผลรอบแรก](../method1_test/results/method1_session1/calibration.json) ใช้มัธยฐานของ 64 readings รวมการอ่านแรก ไม่ตัด outlier และไม่ปัดให้ตรงค่าตัวอ้างอิง การทดสอบรอบสองใช้สมการเดิมโดยไม่ fit ใหม่ ได้ RMSE เทียบค่าตามป้ายประมาณ 0.366 pF

**ข้อจำกัดสำคัญ:** ผลเฉลี่ยรอบสองของ 5 pF อยู่ประมาณ 4.423 pF (-11.53% เทียบป้าย) จึงยังต้องแก้/ประเมินความคลาดเคลื่อนช่วงต่ำก่อนส่งจริง ตัวอ้างอิงมี tolerance +/-5% และยังไม่มีข้อมูลนอกช่วง 5-20 pF โปรแกรมไม่ clamp ค่านอกช่วงให้ดูถูกต้อง ผลนอกช่วงเป็น extrapolation ที่ยังไม่ยืนยัน

กำหนด CPU 240 MHz และคงลำดับจับเวลาใกล้เคียงตัวทดลอง แต่การคอมไพล์ sketch ใหม่อาจเปลี่ยนความหน่วง จึงต้องตรวจค่ากับวงจรจริงอีกครั้ง การผ่านช่วง reference 700-1100 mV เป็นเพียงการตรวจพื้นฐาน ไม่ได้รับรองว่า calibration ใช้ได้เท่ากันทุกแรงดันในช่วงนั้น

## กรณีวัดไม่สำเร็จ

ถ้า reference นอกช่วง, CPU ไม่ใช่ 240 MHz, มี initial_low/timeout แม้แต่หนึ่งครั้ง หรือผลคำนวณไม่เป็นบวก โปรแกรมจะส่ง **Capacitance = 0.00 pF** แทนผลล้มเหลว ไม่ใช้ค่าครั้งก่อน ไม่เฉลี่ยเฉพาะแถวที่เหลือ และไม่วัดซ้ำอัตโนมัติ

0.00 pF ไม่ใช่ค่าที่วัดได้จริง ต้องยืนยันรูปแบบแจ้งความล้มเหลวนี้กับกรรมการก่อนส่ง หากพบใน rehearsal ให้กลับไปใช้ตัวทดลองเพื่อดูสถานะและตรวจวงจร

## Checklist ก่อนส่ง

- [ ] Verify/Upload ผ่านบนบอร์ดจริง (ยังไม่ได้ยืนยันจากเครื่องมือนี้)
- [ ] ตรวจ GPIO2 และ polarity ของ LED ว่าสว่างจริงประมาณ 200 ms
- [ ] กดปกติ/กดค้าง/ปล่อยปุ่มแล้วไม่มีข้อความซ้ำ
- [ ] เปิดเครื่องขณะกดปุ่มค้างแล้วไม่มีผลวัดจนปล่อยและกดใหม่
- [ ] บันทึกผล 5 ครั้งต่อ C ทั้ง 5, 10, 15, 20 pF เปรียบเทียบกับตัวทดลอง
- [ ] ตรวจเวลาจากกดถึงข้อความครบให้ต่ำกว่า 3 วินาทีบนเครื่องจริง
- [ ] ตรวจ format ทีม หน่วย ทศนิยมสองตำแหน่ง และบรรทัดว่าง
- [ ] ไม่มี 0.00 pF จากวงจรผิดพลาดในการ rehearsal
- [ ] ประเมินความคลาดเคลื่อน 5 pF และยืนยันเงื่อนไขการทดสอบกับกรรมการ
- [ ] บันทึกรุ่น firmware/core และภาพวงจรสุดท้าย ก่อนส่งแล้วไม่แก้ไข

คำสั่ง CLI ทางเลือกจากโฟลเดอร์หลัก repository:

```powershell
arduino-cli compile --profile doit_esp32_devkit_v1 Track1/firmware/method1_competition
```

ยังไม่ได้คอมไพล์กับ ESP32 toolchain หรือทดสอบบน hardware ในสภาพแวดล้อมนี้ ต้องผ่าน checklist ก่อนถือว่าพร้อมส่งแข่งขัน
